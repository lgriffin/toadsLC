# Developing Toads LC

The player guide is the [README](../README.md). This page is for whoever changes the addon:
how it is laid out, how to test it, how to build and release the zip, and what is still open.
The design (requirements, JSON contract, architecture) is the Claude Doc
"Toads Loot Priority Addon — Design".

## Layout

Everything that decides who wins is in `ToadsLC/core/` and runs under plain Lua 5.1;
everything that touches the WoW API is one file in `ToadsLC/adapters/`. v1 targets the
TBC Classic client and refuses to load on any other; when the WoW Forever API is published,
only `ToadsLC/adapters/` is ported, and the core, the JSON documents and the site stay the same.

| File | Holds |
| --- | --- |
| `core/Codec.lua` | JSON encode/decode, schema checks with field paths, chunked wire format for addon messages |
| `core/Priority.lua` | spec/role tokens, tier matching (`Rogue:*`, `ROLE:Healer`, `ANY`, named players), sheet wording parser, tooltip labels |
| `core/Resolver.lua` | main spec, then tier, then roll; ties and all-off-spec flagged |
| `core/Crypto.lua`, `core/Wire.lua` | SHA-256, HMAC, PBKDF2, base64; signing and encrypting addon messages with the raid password |
| `core/Session.lua` | session state machine and the message registry (open, responses, votes, proposals, close, re-roll, award, late-join state) |
| `adapters/Tooltip.lua` | Priority block on GameTooltip, ItemRefTooltip and comparison tooltips |
| `adapters/RollParser.lua` | roll lines from `CHAT_MSG_SYSTEM`, built from the client's own `RANDOM_ROLL_RESULT` |
| `adapters/CouncilComms.lua` | `ToadsLC` addon-message prefix, throttled send queue, chunk reassembly |
| `adapters/Frames.lua` | candidate, council and import/export frames |
| `adapters/Roster.lua` | class and spec (talents, inspect, imported `members[]`), council membership |
| `adapters/Sim.lua`, `data/RaidLoot.lua` | `/tlc sim`'s fake kill and raid; boss drop lists generated by `tools/build_loot.py` |
| `adapters/Chat.lua`, `Store.lua`, `Commands.lua` | raid chat, `ToadsLCDB` SavedVariables, `/tlc` |
| `Init.lua` | client check and event wiring |

The client loads files in the order `ToadsLC.toc` lists them, and each module reads the
modules it needs (`local Codec = ns.Codec`) when it loads, so a new file goes in the `.toc`
after everything it reads. `spec/package_spec.lua` fails if the order is wrong, if a Lua file
is missing from the `.toc`, or if shipped code uses something the client does not have
(`io`, `os`, `require`, `loadfile`, `debug`, ...).

## Tests

```sh
sudo apt-get install -y lua5.1 lua-busted lua-check lua-bitop
luacheck .
lua5.1 "$(command -v busted)"            # core, plus the whole addon loaded in a fake client
python3 -m unittest discover -s tests    # packager and item resolver
python3 tools/contract.py                # fixtures, loot tables and a real addon export against the JSON Schemas
python3 tools/build_loot.py --check      # loot tables are up to date with data/loot/overrides.json
python3 tools/package.py --check         # the .toc matches the folder
```

CI runs all of these on every push (`.github/workflows/test.yml`) and uploads the release zip
as a build artifact (`ToadsLC-addon`), so any green run can be downloaded and tried in game.

| Spec | Covers |
| --- | --- |
| `spec/codec_spec.lua`, `priority_spec.lua`, `resolver_spec.lua`, `session_spec.lua`, `wire_spec.lua` | the core modules on their own |
| `spec/adapters_spec.lua` | the whole addon in one fake client: slash commands, rolls, import/export, tooltip, reload, `/tlc sim` |
| `spec/raid_spec.lua` | a leader, an officer and raiders each running the addon, talking over addon messages: a council session end to end, a late officer catching up, a non-council vote ignored, the raid password (right and wrong), and Roster's talent/inspect/`members[]` spec lookup |
| `spec/package_spec.lua` | the `.toc` and load order, and the addon running with only the client's globals |
| `tests/test_tools.py` | `tools/package.py` and `tools/resolve_items.py` |

`spec/wow_mock.lua` is the fake client. `W.install()` / `W.load()` set one up in `_G`;
`W.client({ me = "Hadur" })` makes another in its own global table, and
`W.deliver(clients)` carries addon messages between them as the server would (RAID to everyone
else, WHISPER to the one named).

## Building and releasing

```sh
python3 tools/package.py      # writes build/ToadsLC-<version>.zip
```

The zip holds one top-level `ToadsLC/` folder with the `.toc` and exactly the files it lists,
so players unzip it straight into `Interface/AddOns`. Specs, tools, schemas, fixtures and the
loot JSON stay out. The folder name must match `ToadsLC.toc`, or the client ignores the addon.

To publish a release:

1. Bump `## Version:` in `ToadsLC/ToadsLC.toc` (for example `0.2.0`) and merge it.
2. Tag the merge commit `v0.2.0` and push the tag.
3. `.github/workflows/release.yml` checks the tag matches the `.toc`, builds the zip and
   attaches it to a GitHub release with generated notes.

### Interface number

`## Interface: 20505, 20506` covers both TBC Anniversary client builds that current addons
ship for (BigWigs lists both; DBM lists 20506). If the client shows Toads LC as "out of date",
run `/dump select(4, GetBuildInfo())` in game and add that number to the list.

## Loot tables

`data/tbc-raid-loot.json` lists every Rare-or-better raid drop from Karazhan to Sunwell
Plateau (1037 items) with `itemId`, `name`, `quality`, `slot`, `itemLevel`, `zone`, `boss` and
`phase`, in the same field names the priority JSON uses. Tier tokens and quest items carry
`rewards` (the pieces they buy) and each piece carries `tokens`, so a priority on Helm of the
Fallen Hero can be shown on Voidheart Crown and back again, the way Gargul links them.

- `python3 tools/resolve_items.py priorities.json` fills `itemId`, `zone`, `boss` and `phase` on a
  priority list from the item names, and lists names it cannot place. The CSV converter should run
  its output through this.
- `python3 tools/build_loot.py` rebuilds the file (and `ToadsLC/data/RaidLoot.lua`, the copy `/tlc sim` reads) from the `wow-classic-items` npm package (MIT,
  scraped from Wowhead) plus the hand-checked fixes in `data/loot/overrides.json`. Edit the
  overrides, never the generated file; CI fails if the two disagree.
- Boss names are the in-game encounter names (`Gruul the Dragonkiller`, `Opera Hall`,
  `Reliquary of Souls`), which is what the addon records from `ENCOUNTER_END`. Trash drops have
  `boss: "Trash"`.
- **Gaps:** 133 Sunwell Plateau items (mostly Eredar Twins, M'uru and trash loot, plus the T6
  bracer/belt/boots tokens and their pieces) have `boss: null` because the scrape does not say who drops them.
  Zul'Aman's timed-chest rewards are not in the file. Both are fixed by adding entries to the overrides.

The JSON contract lives in `schemas/` (`toads-loot-priority` v1 and `toads-loot-session`
v1) with the sample documents from the design doc in `fixtures/`.

`fixtures/priority.test.json` is a made-up priority for all 1037 items, for trying tooltips,
sessions and `/tlc sim` in game before the real list exists. `python3 tools/make_test_priorities.py`
regenerates it from the loot tables and the same npm package: each item's tiers come from its
armour or weapon type, class restriction and stats, tier tokens list their classes, and
Dragonspine Trophy keeps the sample's hand-written priority. `tools/contract.py` checks it against
the schema and that it still covers every item in the loot tables.

## Raid password internals

Without a raid password, council traffic is plain JSON on the RAID addon channel: anyone
reading raw addon traffic can see votes and notes, and a modified client could send messages
that look like an officer's. With a password, every message is signed (HMAC-SHA-256 with a
PBKDF2 key; only the key is stored, for 12 hours or until `/tlc end`), and responses, notes,
votes, proposals and state are encrypted. Raiders without it still see the open, close and
award, but cannot verify them, so a forged public message could at worst show a raider a fake
loot frame. A raider's own button press and note travel as a whisper to the leader only. An
officer who skipped `/tlc join` sees sessions as a viewer and is told to join; once they do,
the leader sends them the current state.

## Not done yet

- **Golden priority list.** The CSV converter and the first `toads-loot-priority.json`
  built from the 172-item sheet are not in this repo yet; add the file to `fixtures/` and
  it becomes the golden sample for both repos.
- **In-game checklist.** Everything runs in tests against a fake client; it still needs the
  two-person Karazhan run from the design doc (loot frame, bag, chat-link and comparison
  tooltips, roll timing, export select-all) and a check of the interface number above.
- **Druid ferals.** Talents cannot tell bear from cat, so an uninspected feral is matched
  on `Druid:*` until the site's `members[]` names the spec or the LC sets it from the frame.
- Open questions from the design doc (token set, bare "Priest", tier tokens, who may start
  a roll, multi-item tabs) are unchanged; the code follows the doc's current assumptions.
